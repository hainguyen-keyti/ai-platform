# Review: web front end, UI tests, docs (HEAD 4cd26c8)

**Nothing is blocking.** No data-loss path, no XSS surface, every stuck state has a way out. Eleven should-fix items, then nice-to-haves.

## Should fix

**1. A job is forgotten the moment the person leaves the chat view.** `App.jsx:54-56` unmounts `Chat` when "gallery" or "API" is tapped; `runJob` (`Chat.jsx:284-324`) keeps polling on the dead instance (`waitForJob` has no stop, `api.js:88-100`). Scenario: ask for a picture (a minute), tap gallery to look at old pictures, tap chat: no typing bubble, no Stop, the conversation shows only the question; the person sends again (a second credit, a second turn into the same thread, which `create_job` does not refuse); the first reply lands silently and shows only after reopening the conversation. Fix: keep `Chat` mounted and hide it (`hidden` class) while another view shows, or lift the running job to `Shell`; either way an `alive` ref so a poll stops on unmount.

**2. A finishing job overwrites whichever conversation is open now.** `Chat.jsx:302` and `:305` call `setConversation(...)` for the job's conversation with no check against the current `activeId`; the list rows and New chat (`:401`, `:431`) are not disabled during a job. Scenario: send in A, open B while waiting; when A's job ends, B's row is highlighted and the header says B, but the thread shows A; the next send goes to B (the header is right, the screen is wrong). Same class: the loader at `:132-136` has no cancellation, so tapping A then B on a slow link can land A last. Fix: an `activeIdRef` kept in sync, `if (activeIdRef.current !== created.conversation_id) return` before each `setConversation` in `runJob`; a `live` flag in the `[activeId]` effect like the providers poll at `:161-172`.

**3. An expired token leaves a signed-in shell with no session.** `api.js:27-30` clears the token on 401 but nothing tells `Shell`, whose `user` stays set (`App.jsx:11, 28`). Scenario (daily, TTL is 24h, `config.py:20`): a tab left open overnight; the first send shows "session expired, sign in again" in red, every later call too, media fetches go out as `Bearer null` (`api.js:67, 78`); the Login page appears only after pressing "sign out". And the other way round at `App.jsx:19`: `api.me().catch(() => setToken(null))` signs the person out on any failure, a network blip or `docker compose restart api` during a reload included. Fix: an `onUnauthorized` hook in `api.js` that `Shell` sets to `() => setUser(null)`; at `App.jsx:19` clear only on `err.status === 401` (the request already did), otherwise keep the token and show the error.

**4. Sign out never revokes the session.** `App.jsx:22-25` only forgets the token; `POST /auth/logout` exists (`auth.py:66-69`) and `api.js` has no `logout`. A token copied from a shared machine works until its TTL. Fix: `api.logout()` (ignore its failure) before `setToken(null)`.

**5. Gallery delete has no confirmation.** `Gallery.jsx:28-35, 58-60`: a 12px "delete" in a two-column phone grid removes the file for good (`media.py:89-96`) on one tap; the chat's delete (`Chat.jsx:375`) and the key revoke (`ApiKeys.jsx:49`) both confirm. Fix: `window.confirm` with a new string pair, or an undo. ui_smoke never clicks it.

**6. The gallery shows at most 100 items under a heading that counts them all.** `Gallery.jsx:20-22` calls `/media` with no `limit`/`offset`; `media.py:58` defaults to 100 and returns `total`. At 100 credits a day a person reaches "Gallery (137)" with 100 tiles and no sign that 37 are missing. Fix: "show more" with `offset`, or say "100 of 137". (Same shape for the list: `conversations.py:28` limit 50, `api.js:49` never asks for more; search covers it, so nice to have.)

**7. Failure kinds other than two show the worker's raw English sentence.** `Chat.jsx:315-317` softens only `503` and `provider_misconfigured`. A job that fails `no_worker` (the worker stops after the turn was queued; the person's own poll fails it, `jobs.py:512`) prints "no worker is serving chatgpt right now" in red, while the same condition at send time shows the translated amber notice; `stranded` ("the worker lost this job 3 times") likewise. The HANDOFF knows this for `provider_error`; it is wider. Fix: treat `err.kind === 'no_worker'` like 503, and map `stranded`/`provider_error` to a translated sentence, keeping the raw text in the title attribute.

**8. The web image ignores the lockfile.** `web/Dockerfile:5-6` copies `package.json` only and runs `npm install`, so each build resolves `^` ranges afresh while `package-lock.json` sits unused; the compose keeps that `node_modules` in an anonymous volume (`docker-compose.yml:32-33`), so a teammate's container can run different minors than the owner's. Fix: `COPY package.json package-lock.json ./` and `npm ci`.

**9. `.env.example` promises api settings the api never receives.** `.env.example:25-60` documents `NO_WORKER_SECONDS`, `PROVIDER_HOLD_SECONDS`, `JOB_LEASE_SECONDS`, `JOB_MAX_ATTEMPTS`, `DEFAULT_QUOTA`, `CLOCK_OFFSET_SECONDS` ("set on the api", "DEFAULT_QUOTA at signup"); `docker-compose.yml:9-14` passes five variables, none of these, so `config.py` runs on its defaults whatever `.env` says. The HANDOFF names only `PROVIDER_HOLD_SECONDS`; all six are the same. Fix: list them under the api service in compose (or `env_file`), and add `TOKEN_TTL_HOURS` to the example.

**10. Setup docs for a new machine.** `CLAUDE.md:13-24` has no step for `cp .env.example .env` (compose refuses to start without three values, `docker-compose.yml:12-14`), none for making `~/cloakbrowser-env` with cloakbrowser in it (`run-worker.sh:8-13` and `acceptance.py:419-422` both exit without it), nothing saying the full gate's `npm run build` needs node and `npm install` on the host, and nothing saying the web only works on the machine running it (`VITE_API_URL: http://localhost:3000`, `docker-compose.yml:26`; the API page's example prints that same localhost address for everyone, `ApiKeys.jsx:70-78`). There is no README. `PROJECT.md:23` still says "API (Hono/TS)"; it is FastAPI/Python, and the worker runs on the host, not in Docker. `docs/specs/2026-09-23-ai-platform-design.md` is marked "Approved" and describes TypeScript+Hono (`:31`), a Dockerised worker (`:278-285`), Zustand + React Query (`:300`), 1h JWT with refresh tokens (`:346`), an Admin page (`:298`), `/admin/providers` routes (`:248-249`) and `scripts/login-chatgpt.py` (`:114-116`); none exist. Fix: a "superseded by the code, see docs/agent/PROJECT.md" line at its top, and PROJECT.md's diagram corrected.

**11. Error text is English in both languages.** Every string a person reads in an error comes from `api.js` (`:29, 37, 69, 80, 93`) or the api's `detail` (`quota exhausted`, `wrong email or password`, `request failed (422)`), plus the typing bubble's phases straight from the worker (`TypingBubble.jsx:35-37`: "reply started", "making a video", "requeued"). The string tables themselves are complete (66 keys each, every `t.x` used exists). Fix: a `t.errors[status|kind]` map for the common ones (401, 402, 409, 422, 503, no_worker), phases mapped in `TypingBubble`, raw text as a fallback.
